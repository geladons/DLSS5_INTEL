# Changelog

All notable changes to this project. The day-by-day engineering log with
measured numbers lives in [DEV_STATE.md](DEV_STATE.md); this file tracks
user-visible milestones.

## Unreleased — live-test fixes batch (2026-10-01)

### Fixed (field-verified)
- **RDR2 boots**: it renders via **Vulkan**, not DX12 — a deployed dxgi.dll
  proxy stalled its init deterministically (real signed dxgi.dll boots
  fine; suspected anti-tamper reaction to a foreign dll). Game config is
  now `mode: vulkan` (implicit layer, in-process chain); verified to the
  main menu with processing + frame generation healthy.
- m12-dxgi: export ordinals now mirror system dxgi.dll slots 1-20 —
  ordinal-based callers were landing on entirely wrong stubs; per-object
  vtable swap replaces shared-.rdata patching; forwarders log call
  entry/exit.
- m11-layer: a raw frame is never inserted into a processed stream —
  connect-refused (daemon absent) vs transport-timeout (daemon busy) are
  handled differently, the last processed frame is held through fresh
  outages, and socket probes are paced (no 1.5 s stall per present).
- **Presets/gain/blend/sharpness/frame_gen now apply LIVE to a running
  in-process game**: the manager's knob file (%TEMP%\m13_phase30_knobs.json)
  carries engine knobs; the m11 layer and m12 proxy poll it (mtime, 250 ms).
  Env vars remain the launch baseline.

### Media tab rework
- Auto-preview on add, Apply button, explicit Save (full-res via
  SavePolicy; previews only preview), preview at reduced res
  (media_preview_max, ~4x faster), zoomable Before/After viewer
  (wheel zoom, drag pan, linked views), stale-job dropping.

### UI
- Manager window now opens at 1280x900 with all controls visible (measured
  widget-tree requirement was 1725x1017 vs the old 1024x760); Settings tab
  scrolls; media tab keeps its control columns at narrow widths.

## Unreleased — Stage 25 release-blocker batch (2026-09-30)

### Licensing
- Relicensed from MIT to Apache-2.0 (LICENSE, NOTICE, SPDX headers). Public
  revisions up to cf04e26 stay MIT.

### Fixed
- Temporal shimmer on static content: vendor noise seed pinned (was keyed
  by frame index); regression test `chain/test_noise_seed.py`.
- Positional HUD masking removed entirely (field test: covered game content
  and looked worse than no mask). Phase30 `auto_mask` (vendor skin/structure
  conditioning) is unrelated and stays.
- Game launch: dedicated `GameLauncher` (timed steps, structured
  `[launch]` log lines, guards against double launch / second game), no
  config mutation mid-launch, no Witcher 3 dx11->dx12 auto-switch or
  sister-dir deploy (crashed the Streamline DX12 binary); action queue
  watchdog (`WorkerSupervisor`) so a stuck job no longer freezes the UI.
- Frame Generation actually runs: real 1:2 cadence (every 2nd present
  through the network) with the frame between generated by
  motion-compensated residual transfer of the last processed frame
  (`dlss5_framegen_transfer`). Previously FG never fired with the default
  frame pacing and, when it could, blended processed with raw frames.
  x64 in-process only; UI label says so.
- Performance presets (render scale < 1.0) reconstruct detail: the neural
  residual is upscaled and added onto the full-res native frame instead of
  presenting a bilinear blow-up of the low-res result (1-px stripe energy
  kept: 0.2% -> 100%).
- In-game overlay never takes the game's foreground (exclusive-fullscreen
  games no longer minimize); photo-mode freeze and focus steal are opt-in
  (`overlay_freeze`, `overlay_focus`, both default off).
- x64 games (Witcher 3, Metro Exodus, RDR2) no longer die on the first
  processed frame: the manager now passes the weights path and shader
  directory to every launch (`DLSS5_WEIGHTS_PATH`, `DLSS5_SHADER_DIR` and
  NR_LAYER_* aliases - previously only the daemon got `--weights`), and
  the chain reports init failures through the C ABI instead of calling
  `exit()` inside the host game; a failed init is latched, not retried
  per frame.
- GTA IV (x86 daemon path) no longer strobes processed<->native frames on
  daemon timeouts: transient failures hold the last processed frame of the
  same size, a never-answering daemon stays native, and degenerate
  sub-64 px swapchains (menu strips) bypass the daemon entirely.
- GTA V "foreign DLLs" confusion: the state label now explains Enable
  backs foreign dlls up; duplicate game entries that differed only by
  path separators are merged on config load.
- Overlay no longer activates on show even transiently (WS_EX_NOACTIVATE
  applied before first map, SW_SHOWNOACTIVATE, popdown covered); GTA IV
  minimize root cause was `overlay_focus:true` in config - reset it.
- Frozen-frame live tuning on multi-swapchain games (GTA IV menu strip):
  freeze now latches the largest real swapchain only; knob reprocesses
  target the captured extent; reproc bumps fire after the daemon push.

### Added
- **Media tab** — offline photo/video processing through the chain at
  native scale: photo before/after preview with the live overlay knob
  set, video decode->process->remux keeping fps and audio (ffmpeg,
  downloadable from the tab), batch queue, save policies.
- Per-game **"Window (try)"** checkbox next to Play (-windowed -window),
  plus a free-form per-game `launch_args` field in the game meta.
- Settings -> "Remove all traces...": undeploys our dlls from every
  configured game (restoring parked originals, including sibling dirs),
  unregisters the Vulkan layers, stops the daemon, clears temp
  flags/logs, and optionally removes saved configuration. Foreign dlls
  are reported but never deleted.

### Changed
- `nr_layer_win.c` logs `fg stats: presents/processed/generated/native`;
  overlay logs `[overlay] shown ... fg_before/fg_after`.

### Removed
- Vendored AMD FSR 1.0 EASU/RCAS compute shaders
  (`m8b-live/shaders/fsr_easu.comp`, `fsr_rcas.comp`, `fsr/ffx_a.h`,
  `fsr/ffx_fsr1.h`, MIT) — an experiment superseded by our own bounded
  CAS in `encode.comp`; never wired into a build.
- Leftover `m8b-live/shaders/` copies no build compiles: `standin.comp`
  (the M3 stand-in block, replaced by the real 71-block chain; live
  copies remain in m3/m4/m5) and `m8/round_test.comp` (the M7a rounding
  unit kernel; live copies remain in m7/m8/m9).
- Dead imports in m13 (`logtail`: `time`; `test_launcher` /
  `test_launch_paths`: unused `MagicMock`/`PropertyMock`; `test_stage5`:
  unused i18n names; `_ctrl_validate`, `_ui_smoke` helpers).

## v0.1-demo — 2026-09-25 (M13 v6)

First public demo build.

### Added
- Vulkan implicit layer (x64 + x86) intercepting `vkQueuePresentKHR`,
  gated by `ENABLE_NR_LAYER=1`, with hotkeys `CTRL+ALT+X` (pause/resume)
  and `CTRL+ALT+Q` (unload).
- DX9/10/11 support via per-game DXVK deployment; DX12 support via a custom
  `dxgi.dll` proxy (vtable hook on `Present`, `M12_LIVE=N` frame pacing).
- Frame daemon `m11d` (TCP 127.0.0.1:47990): 16-byte header + BGRA
  protocol, masked-UI passthrough, alpha preserved, NRCT control channel
  (`STATUS` / `SETGAIN` / `SETBLEND`), `--selftest` golden validation.
- Screen/window mode (`m8blive`): DDA capture → 71-block chain → echo-cancel
  compose → click-through Vulkan overlay; live knob file, no restart needed.
- DLSS5 Manager (M13): auto-setup (weights find, layer registration, daemon
  start), game scanner (Steam/Epic/GOG + all-drive PE-based API detection),
  per-game deploy/launch with backup/restore and one-time UAC for
  Program Files, two live knobs (gain 0–16, blend 0–1) in the header and in
  the in-game overlay, photo mode (frozen raw frame + live reprocess),
  EN/RU UI, console-free VBS launcher.
- Interactive before/after comparison page (`docs/compare.html`) with 7
  captured GTA IV pairs (menu, 4 loading screens, 2 in-game).

### Known limitations
- Performance: GEMM-bound chain (~135 ms @ 500×500, ~0.9–1.1 s/frame at
  1080p-class) — a slideshow; the #1 open problem.
- Screen/window mode is slow (tens of seconds for frame 0 at 1440p) and
  rough around the edges.
- In-game overlay works partially: mouse capture/release conflicts with some
  games; exclusive fullscreen may minimize the game.
- Daemon and screen mode are mutually exclusive at 16 GB VRAM (enforced by
  the manager).
