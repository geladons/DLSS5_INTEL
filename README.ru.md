# DLSS5_INTEL

**DLSS 5 Neural Rendering, работающий вживую на Intel Arc — фанатский исследовательский проект.**

Проект берёт настоящую нейросетевую модель DLSS 5 (71-блочный граф DLSSNR) и
запускает её на **видеокартах Intel Arc** через Vulkan
(`VK_KHR_cooperative_matrix`, XMX-ядра) вместо тензорных ядер NVIDIA. Обработка
идёт **в реальном времени на презенте кадра** — для Vulkan-игр через implicit
Vulkan-слой, для DirectX 9/10/11 — через DXVK + тот же слой, для DirectX 12 —
через собственный DXGI-прокси. Режим «экран/окно» обрабатывает весь десктоп
или отдельное окно через DDA-захват и кликабельный поверхностный Vulkan-оверлей.

> ⚠️ **Фан-проект. Не продукт.** Не аффилирован с NVIDIA и Intel и не
> одобрен ими. Мы **не используем код NVIDIA** и **не распространяем веса
> модели** (проприетарные данные NVIDIA). DLSS и NVIDIA — товарные знаки
> NVIDIA Corporation. Всё здесь — исследование и инженерная демонстрация.

Это работающий proof-of-concept, а не инструмент на каждый день. Что вас ждёт
сегодня:

| Область | Статус |
|---|---|
| Vulkan-игры (implicit-слой) | ✅ Работает — проверено end-to-end на vkcube и вживую на RDR2 (Vulkan) |
| DX9 / DX10 / DX11 (через DXVK → Vulkan) | ✅ Работает — проверено вживую на GTA IV (DX9, 32-бит) |
| DX12-игры (собственный прокси `dxgi.dll`) | ✅ Механика работает — проверено в оконном режиме |
| Автоустановка нужных DLL в папку игры | ✅ Работает — автоопределение API, свой набор DLL на режим, один запрос UAC для игр из Program Files |
| Автопоиск игр | ✅ Работает — манифесты Steam / Epic / GOG + скан всех дисков, определение API через PE (находит настоящие игры, а не каждый `.exe`) |
| Внутриигровой оверлей (`CTRL+ALT+G`) | ✅ Работает — в стиле Game Bar: topmost, никогда не забирает фокус у игры (нет сворачивания), отпускание курсора (`AttachThreadInput`); заморозка кадра (фото-режим) и захват фокуса — опциональные настройки |

| **FPS и производительность** | 🟡 **На ретро/низких разрешениях уже играбельно; 1080p-класс — пока демо.** GTA IV 800×600 @ scale 0.67 — ~45 мс round-trip движка, **23.1 FPS в среднем по внутриигровому бенчмарку**. Полный 71-блочный чейн: ~210 мс @ 960×576 (scale 0.50) и ~547 мс селфтест / 767 мс steady @ 1080p native на Arc Pro B50 (ускорение на 320 мс по сравнению с v0.2). FrameGen — реальный каденс 1:2 (захват среднего кадра + интерполяция двух последних обработанных якорей; работает и внутри процесса на x64, и по TCP на x86). См. [docs/BENCHMARKS.md](docs/BENCHMARKS.md) |
| **Временнáя стабильность** | 🟡 Motion-compensated residual-пайплайн: байт-в-байт статичный выход, остаток едет с контентом (а не с клеткой экрана), DC-корректная оценка движения отсекает фейды, аттенюация релизится по верификации остатка (нет ~3-секундных шлейфов «проявления» после движения). Прогоняется автоматическим replay-гейтом на реальных захватах GTA IV |
| Пауза / возобновление | ✅ `CTRL+ALT+X` — пока обработка на паузе, игра идёт в полный FPS |

Долг по производительности — известная главная проблема (см.
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#performance)); корректность
нейропрохода валидирована бит-в-бит против PyTorch-эталонов.

## Что нового по сравнению с `v0.1-demo`

`v0.1-demo` (25.09.2026) был первым публичным слепком: он доказал, что
транспорт работает end-to-end — слой, маршруты через DXVK, DX12-прокси,
даемон, режим экрана, менеджер — но был медленнее, работал только через
TCP и не имел рабочей генерации кадров. Текущий слепок сохраняет ту же
внешнюю оболочку (та же структура бандла, те же крутилки, те же сценарии)
и меняет внутренности:

| Область | `v0.1-demo` | Текущий слепок |
|---|---|---|
| x64-игры (Vulkan/DX12) | каждый кадр ходил по TCP в `m11d` (127.0.0.1:47990) | `d5c_chain.dll` грузится внутри процесса через C ABI — без сокета, транспорт ~1.5–2.5 мс; TCP остаётся запасным путём |
| x86-игры (32-бит) | TCP-путь через даемон | по сути без изменений (даемон их по-прежнему обслуживает), плюс защита от флапа: при кратковременных сбоях держится последний обработанный кадр вместо стробоскопа «обработанный↔сырой», вырожденные свопчейны < 64 px обходят даемон |

## Как это работает (коротко)

```
кадр игры ──present──► ┌ Vulkan-слой / DXGI-прокси / DDA-захват ┐
                        │ заголовок 16 байт + BGRA, TCP 127.0.0.1:48990 │
                        └──────────────► даемон m11d ◄──────────────────┘
                                       decode → features → featpack
                                       → 71-блочный чейн DLSSNR (упор в GEMM)
                                       → head → residual → высокочастотный фильтр
                                       → эхо-подавление (feedback accumulate)
                                       → compose (крутилки gain + blend)
                                       → encode → readback ──► обратно в свопчейн
```

- **Vulkan-игры** — implicit Vulkan-слой перехватывает `vkQueuePresentKHR`,
  отправляет кадр даемону и записывает обработанный кадр обратно.
- **DX9/10/11** — DXVK для конкретной игры гонит D3D через Vulkan, дальше
  работает тот же слой.
- **DX12** — прокси `dxgi.dll` (vtable-хук на `Present`) делает тот же
  раундтрип напрямую.
- **Режим экрана/окна** — DDA-дубликация десктопа → CPU-мост → тот же чейн →
  полноэкранный topmost кликабельный Vulkan-оверлей.
- **Менеджер (M13)** — Python/Tk только на стандартной библиотеке:
  автоустановка, поиск игр, деплой/запуск на игру, две живые крутилки,
  внутриигровой оверлей, интерфейс EN/RU.

Подробности, карта модулей и разбор производительности:
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Возможности

- Живая нейропостобработка в **Vulkan, DX9, DX10, DX11, DX12**
- **Автоинъект**: нужные DLL копируются рядом с исполняемым файлом игры под
  определённый API (бекап перед перезаписью, восстановление поддержано)
- **Автопоиск игр**: библиотеки Steam, манифесты Epic, реестр GOG, скан всех
  дисков с разбором PE (импорты, delay-load, wide-строки D3D) — находит
  настоящий рендерер и его битность
- **Две живые крутилки** — `gain` (сила эффекта, 0–16) и `blend` (микс
  эффекта, 0–1; при 0 — побитовый прозрачный проход) — в шапке менеджера и во
  внутриигровом оверлее; сброс каждого слайдера; сохраняются в конфиге
- **Фоторежим** — `CTRL+ALT+G` замораживает сырой кадр, каждый поворот крутилки
  перерабатывает *исходный* кадр на лету, закрытие панели продолжает игру
- **Вкладка «Медиа»** — офлайн-обработка файлов DLSS 5: фото (PNG/BMP,
  JPEG при наличии ffmpeg) и видео; тот же набор ползунков живьём
  пересчитывает выбранное фото с предпросмотром «до/после»; видео
  декодируется покадрово, обрабатывается в нативном разрешении и склеивается
  обратно с исходными fps и звуком. Пакетная очередь + галочка «оконный
  режим» у кнопки Play
- **«Удалить все следы»** — кнопка в настройках снимает наши DLL со всех
  игр (восстанавливая оригиналы), отключает Vulkan-слои, глушит демона и
  чистит флаги/логи
- Горячие клавиши: `CTRL+ALT+G` оверлей · `CTRL+ALT+X` пауза/возобновление ·
  `CTRL+ALT+Q` выгрузить слой
- Интерфейс EN/RU
- Валидация бит-в-бит против PyTorch-эталонов (features 15/16 каналов
  bit-exact, head meandiff ≈ 0.0083 = уровень fp16-шума)

## Требования

- Windows 10 / 11 (проверено на Windows 11)
- **Intel Arc с 16 ГБ VRAM рекомендовано** (проверено: Arc Pro B50; арена
  движка резервирует ~0.8 ГБ с FP16-паком / ~3.9 ГБ с INT8-паком при
  загруженных весах — на меньших картах не проверялось)
- Vulkan 1.3+ с `VK_KHR_cooperative_matrix` (класс Xe2)
- Python 3.10+ для менеджера (лаунчер находит его сам)
- Веса модели — **не входят в комплект**, см. ниже

## Быстрый старт (релизный бандл)

1. Скачайте релизный бандл из [Releases](../../releases) (или соберите из
   репозитория скриптом
   [`release/assemble-release.cmd`](release/assemble-release.cmd)).
2. Положите файл весов в папку `weights\` бандла — точное имя и формат в
   [docs/weights-format.md](docs/weights-format.md).
3. Запустите **`DLSS5 Manager.vbs`** (двойной клик; чёрного окна консоли нет).
4. Вкладка «Игры» → выберите карточку игры → **«Включить DLSS 5»** (один запрос
   UAC для игр из Program Files) → **«Играть»**.
5. В игре: `CTRL+ALT+G` — панель управления на замороженном кадре.

**Сценарий для медиа:** откройте видео, сделайте пару скриншотов,
загрузите их на вкладку «Медиа», подберите ползунками нужный вид на фото
(живое «до/после»), затем поставьте видео в очередь — оно отрендерится с
этими настройками. Пакетный режим обрабатывает целую папку фото или
несколько видео за прогон. Для видео нужен `ffmpeg` — вкладка умеет
скачивать его по кнопке.

**Предупреждение об античите:** не включайте в онлайн-играх (PUBG, CS2,
GTA Online, всё с ядерным античитом) — DLL-инъекция может быть расценена как
чит. Только одиночные игры.

## Веса

Веса модели DLSSNR — **проприетарные данные NVIDIA и не распространяются** — ни
в репозитории, ни в релизном бандле. Для запуска демки нужен ровно один файл:

| | |
|---|---|
| Имя файла | `dlssnr-logical.safetensors` |
| Формат | Safetensors, раскладка `dlssnr-logical-v18` |
| Содержимое | 649 тензоров (579 × F16, 70 × F32), 71 группа блоков сверху — стек DLSSNR в стиле ViT |
| Размер | ~291.5 МБ (≈325 МБ резидентно в VRAM) |
| SHA-256 | `203b0af3be94078cfd17a71adc4628cffd960a4d435e4820fe994ddd9493a6a5` |
| Куда | папка `weights\` бандла или любой путь через `--weights` |

Как получить такой файл — ваше дело и дело вашего локального права; загрузчик
просто читает формат Safetensors выше. Детали:
[docs/weights-format.md](docs/weights-format.md).

## Благодарности и атрибуция

### Апстрим и производный код
Проект начался в сентябре 2026 с транспортного слоя
[dlss-nr-on-intel](https://github.com/UzbekUnknown/dlss-nr-on-intel) автора
**UzbekUnknown** (Apache-2.0). Этот код используется до сих пор и сохраняет
оригинальные уведомления (см. также [NOTICE](NOTICE)):

- `dlss5/m11-layer/nr_layer_win.c` — порт `src/layer/nr_layer.c` на Windows
  (перехват `vkQueuePresentKHR`; с тех пор сильно расширен: in-process C ABI,
  каденс генерации кадров, переиспользование повторных кадров, fail-fast TCP)
- `publish.glsl` (копии в `dlss5/*/shaders/`) — byte-verbatim
  `src/gpu/publish.glsl`, контракт точек округления вендора
- транспортные шейдеры `decode` / `encode` / `features` / `rescale` — порты
  численной части `src/ref/nr_image.c` / `nr_daemon.py` (CAS, residual-
  реконструкция и accumulate-режим в `encode`/`compose` — наши)
- `golden.py` (в `m7-graph-proto` / `m8-full-chain`) — семантика референса
  на основе `src/ref/nr_model.py`

Всё остальное — оригинальный код этого репозитория: исполнитель 71-блочного
графа DLSSNR (`dlss5/chain`: `d5c::ChainEngine`, GEMM на cooperative matrix,
fused flash attention, INT8-путь, векторизованный pool, arena-аллокатор),
весь temporal-пайплайн стабильности (`temporal_nr` / `temporal_stats` /
`motion_est` — residual-холд, motion-компенсация состояния, DC-корректный
still-match, верифицированный релиз аттенюации), каденс генерации кадров
(mid-capture интерполяция + перенос остатка), residual-реконструкция при
render scale < 1, демон `m11d`, DX12-прокси `m12-dxgi`, screen/window-
приложение `m8b-live`, менеджер `m13` (лаунчер, деплой, оверлей, сканер игр)
и автотест-стенд `tools/autotest` (replay-гейты, детекторы дефектов,
DDA-захват, виртуальный геймпад).
